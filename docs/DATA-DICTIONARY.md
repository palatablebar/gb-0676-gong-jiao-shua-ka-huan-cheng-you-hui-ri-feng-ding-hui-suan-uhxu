# 数据定义

刷卡事件以event_id去重，card保留前导零。route支持1路/01等别名。event_time必须带偏移；业务日为Asia/Shanghai。result仅success可作为行程，失败刷卡隔离。reported为实扣人民币元。票价F1至2026-11-01前为2元，F2为2.50元。

跨线路换乘必须在上一次实际付费行程后60分钟内，恰好60分钟排除。同线路无优惠；零付费行程不能延长换乘锚点。先扣1元换乘优惠，再对卡号业务日施加6元封顶。每条基本票价=实算扣费+换乘优惠+封顶优惠。

业务ID和超大整数按文本保形；Decimal参与数量金额计算，对外序列化为字符串。哨兵集合定义在app/values.py，缺失值不能当零。所有时间带UTC偏移，先转UTC比较，业务日按指定地区划分。区间统一[start,end)。重复业务键保留第一条、完全相同行计重复；值冲突行隔离且保留原值。空文件、全空白、仅表头分开拒绝。

运行清单包括输入sha256、规则版本、参数、生成时刻与耗时。源行编号以CSV解析器的物理结束行号表示，引号内换行不增加记录数。输入超过4MB返回413，非法表头和类型返回422，失效版本复核返回409。

## 离线分段补传（采集水位账）

车载机按段序号 seq（从1起）补传，每段载荷为 `{"events":[刷卡事件,...]}`，事件列与刷卡CSV一致。服务端按载荷 SHA-256 存校验和：同序号同校验和视为重试，仅累加 duplicates；同序号异校验和返回 SEGMENT_CONFLICT 拒绝覆盖；客户端可传 expected_version 做乐观并发控制，不符返回 STALE_VERSION(409) 且不写入。

每台车载机维护：contiguous_seq（连续高水位，仅在 1..N 全到齐时推进）、continuous_range（已连续区段）、gap_ranges（缺口序号区间，如 [[3,3]]）、pending_segments（越序到达的待补段）。连续区段事件走线路、票价、行程、优惠回算定稿卡日应收（confirmed_total，含换乘/封顶）；待补段事件不参与定稿，只按基础票价累计 pending_exposure 敞口。gap_ranges 或待补段非空时卡日状态为“缺口未核清·暂缓封存”，封存接口返回 GAP_OPEN(409)；补齐后重算，封存快照含 sha256 且重复封存幂等。水位版本随每次真实新增段自增，重试不自增。
